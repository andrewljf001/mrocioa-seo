# Web Serial Debugger — Future Ideas

本文档只记录尚未进入正式发行范围的方向，不代表已经上线或承诺在某个版本交付。

## 远程只读观看（桌面串口主机 + 移动端 Viewer）

### 可复用范围

- 建议做成统一的 `MROCIOA Lab Viewer` 模块，供后续网页测试工具共同使用。
- Web Serial、WebUSB、WebBluetooth、网络诊断和其他能输出结构化状态或日志的网页工具都可接入。
- 设备权限始终保留在测试主机；观看端只接收工具发布的数据，因此可使用不支持相关硬件 API 的手机、平板或电脑。
- 优先同步结构化日志、状态、图表点和解析结果，不传输整屏视频，以降低延时、流量和画质损失。

### 使用目标

- 桌面端用户在 Chrome 或 Edge 中连接真实串口设备。
- 操作员主动点击 `Share session`，获得临时链接、短码或二维码。
- 手机和平板可扫描二维码或打开临时链接；另一台电脑通过复制临时链接或输入 6–8 位短码加入。
- 二维码只编码同一个临时链接，不建立另一套分享会话。
- 手机、平板或另一台电脑加入后，可实时查看当前调试画面。
- 移动端不需要 Web Serial 支持，也不直接访问串口设备。

### 建议的第一阶段范围

- 默认只读：观看连接状态、串口日志、图表、协议解析结果和当前布局。
- 不允许观看者发送指令、上传文件、切换 DTR/RTS、修改波特率或控制串口。
- 分享必须由串口主机主动开始，并可随时一键停止。
- 分享会话使用短时随机令牌，支持一键复制链接，默认自动过期，可设置最大观看人数。
- 页面明确显示正在共享以及当前观看人数，避免操作员无感知地泄露调试数据。
- 主机关闭页面、断开共享或超时后，观看链接立即失效。

### 隐私与传输建议

- 优先采用 WebRTC 传输实时数据，服务器只负责会话建立和信令协调。
- 不在服务器保存串口日志；无法直连而必须使用中继时，也不做内容持久化。
- 传输内容应加密，分享链接不可被搜索引擎索引，也不进入 Sitemap。
- 对分享码进行速率限制，避免被枚举。
- 在共享前提醒操作员检查日志中是否包含密钥、设备序列号或客户数据。

### 延时目标（网络正常时的工程估算）

- 同一局域网、WebRTC 直连：约 `50–200 ms`。
- 公网同地区、WebRTC 直连或低延时中继：约 `150–500 ms`。
- 跨地区或必须使用中继：约 `300 ms–1 s`，网络拥塞时可能更高。
- 若改为整屏视频共享，通常约 `0.5–2 s`，不建议作为默认实现。
- 测试主机必须在收到设备数据时写入源时间戳；Viewer 的显示延时不能改变或替代原始测量时间。

### 后续单独评估

- 远程控制不是只读观看的一部分。如以后需要远程发送命令，应采用独立开关、逐次授权、明显警告和完整审计提示。
- 是否同步全部历史日志，或只从观看者加入时开始推送。
- 是否提供二维码、同局域网直连、公共互联网中继和企业自托管信令服务。
- 弱网重连、多人观看、超大日志流量和图表降采样策略。

### 版本边界

- 该功能未包含在 `1.0.1`。
- 进入开发前应单独冻结需求、完成威胁模型与隐私评审，再确定版本号。
